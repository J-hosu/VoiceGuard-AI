# 모델 구성

VoiceGuard가 쓰는 모델과 쓰지 않는 모델을 한곳에 모았다. 모델마다 성능, 어디서 도는지, 쓰는 이유와 쓰지 않는 이유를 적는다.
기준은 2026-11-16 시연 서버 설정이다.

- 실시간 전사: GPU의 Whisper large-v3
- 통화 중 재전사와 통화 뒤 전사: 리턴제로

자세한 측정은 [전사 정확도](transcription.md), [탐지 정확도](detection.md), [학습 기록](../MODEL_TRAINING_LOG.md)에 있다.

## 지금 쓰는 모델

| 역할 | 모델 | 도는 곳 | 성능 | 쓰는 이유 |
| --- | --- | --- | --- | --- |
| 실시간 전사 (최근 20초 화면, 실시간 경고가 읽는 글) | Whisper large-v3 원래 모델 (faster-whisper, float16, beam 5) | GPU 필요 | 실시간 조각 CER 9.24%, 파일 전체 5.81%, 조각당 0.13초(GPU를 혼자 쓸 때) | 사기 녹취의 전화번호를 그대로 적는다. 사기 녹취 24건 모두 탐지, 정상 녹음 오경보 0/32 |
| 통화 중 재전사와 화자 구분 | 리턴제로 파일 전사 (sommers, 화자 2명 지정) | 리턴제로 | 정리된 글 CER 4.06%, 화자 정확도 83.7–90.4%, 화면 반영 약 23초 | 실시간 조각에는 화자 정보가 없다. 정리된 글이 실시간 조각보다 정확하다 |
| 통화 뒤 전체 재전사, 녹음 파일 분석 | 리턴제로 파일 전사 (화자 2명) | 리턴제로 (실패하면 GPU의 large-v3) | CER 6.28%, 화자 문장 정확도 98.8% | 사람 단위 말풍선을 만든다 |
| 보이스피싱 통화 분류 | KLUE-RoBERTa v5 (가린 개인정보 자리를 채워 다시 학습) | GPU가 있으면 GPU, CPU로도 됨 | 아래 표 | 아래 표 |
| 문자(스미싱) 분류 | KLUE-RoBERTa (스미싱 문자로 학습) | GPU가 있으면 GPU, CPU로도 됨 | 따로 뗀 평가 정확도 99.4% | Claude 판단과 40:60으로 합친다 |
| 유사 사례 검색, 위험 문구 규칙 | 학습 모델이 아님 (단어 빈도 비교, 규칙) | CPU | – | 근거로 보여 줄 비슷한 사례와 신호를 찾는다 |
| 대화 흐름 판단(상태 추적기), 대응 에이전트, 문자 판별 보조 | Claude Haiku 5.5 | Anthropic API (통화 글을 보냄, 음성은 안 보냄) | – | 학습 데이터에 없는 새 수법을 대화 흐름으로 잡는다 |
| 문서 위조 판별, 수사 분석, 신종 수법 카드, 탐지 근거 설명 | Claude Opus 5.5 | Anthropic API (문서 사진·글을 보냄) | 문서 판별 시험 세트 95.7% (위조 14/15, 진짜 오판 0) | 판단 근거를 글로 설명해야 하는 일 |

**통화 분류기 v5** (2026-11-16부터 서비스, 앞 모델 v3c와 같은 평가)

| 평가 (기준 0.7) | v5 | v3c |
| --- | ---: | ---: |
| Whisper로 받아 적은 AI Hub 정상 녹음 1,400건 · 한 번이라도 경고 | **1.1%** | 2.0% |
| Whisper로 받아 적은 금감원 사기 녹취 258건 · 탐지 | **99.6%** | 97.7% |
| 가린 자리를 채운 정상 통화(학습 데이터 평가 몫) · 한 번이라도 경고 | **4.1%** | 5.5% |
| 피해자가 실제 번호를 말한 사기 80통 · 3마디 시점 탐지 | **72 → 70** | 74 → 63 |
| v2 평가 통화 837건 · 사기 탐지 (통화 전체 / 3턴) | **99.7%** / 88.3% | 99.3% / **89.3%** |
| AI Hub Validation 정상 5,041건(가림을 지운 글) · 한 번이라도 | 0.9% | **0.7%** |
| 실제 정상 녹음 32개 · 오경보 | 0건 | 0건 |
| 따로 쓴 대본 12종 (분류기 단독) | 11/12 (카드 배송 사칭 스미싱을 놓침) | **12/12** |

v3c는 정상 상담의 이름·번호가 지워진 데이터로 배워서, 실제 이름과 번호가 나오는 통화에서 오경보가 늘었다. v5는 가린 자리를 그럴듯한 값으로 채워 다시 학습한 모델이고, 실제 녹음 전사에서 오경보를 절반으로 줄였다. 분류기만으로는 카드 배송 사칭 대본 하나를 놓친다. 화면 위험도의 70%는 Claude 추적기가 정한다([학습 기록](../MODEL_TRAINING_LOG.md)).

추가 학습한 Whisper 세 모델의 공통 원인은 학습 대본의 가림 처리다. AI Hub 대본은 개인정보를 'ㅇㅇㅇ'로 가렸지만 녹음에서는 사람이 그 자리를 소리 내 읽었다. 그래서 모델이 소리 내 읽은 번호를 지우거나, 대본 규칙대로 숫자를 적는 법을 배웠다([전사 정확도의 한계](transcription.md#한계)).

## 학습 데이터의 가림 처리

공개 데이터는 개인정보를 가려서 배포하고, 가린 방식은 출처마다 다르다. 우리가 학습시킨 모델 가운데 이 영향을 받는 것은 둘이다.

- **Whisper 추가 학습:** 대본이 'ㅇㅇㅇ'로 가린 자리를 녹음에서는 소리 내 읽었다. 그래서 모델이 소리 내 읽은 번호를 지우는 법을 배웠다. 탐지 자체는 유지됐지만, 번호로 다른 통화와 잇는 수사 기능이 망가진다. 그래서 쓰지 않는다.
- **통화 분류기 v3c:** AI Hub 정상 상담 3,901건 중 87%에서 이름·번호·주소가 지워진 채 학습됐다. 생성 사기 통화에는 '000-00-0000' 같은 0 번호가 남았다.
  - 통화 전체 판정에는 영향이 없었다.
  - 통화 첫 1–3마디에서는 지름길이 생겼다. 이름과 직함으로 소개하는 정상 통화가 잠깐 높게 나오고, 피해자가 실제 번호를 말하는 사기 통화는 초반 탐지가 늦어진다.
  - 가린 자리를 Sonnet으로 채워 다시 학습한 v5는 이 두 번째 문제를 거의 없앴고, 실제 녹음 전사의 오경보도 절반으로 줄였다. 2026-11-16부터 v5를 쓴다. 이름+직함 소개 문제는 남았고, 분류기만으로는 카드 배송 사칭 대본 하나를 놓친다([학습 기록](../MODEL_TRAINING_LOG.md)).
- **문자 분류기:** 링크와 전화번호가 실제 값으로 들어 있어 다시 처리하지 않았다. 정상 문자 11%에 있는 '***'은 실제 알림 문자에서도 쓰는 이름 가림이다.
- **영향 없는 것:** 원래 Whisper, 리턴제로, Claude(우리가 학습시키지 않음), 화자 분리(음성만 봄).

평가 세트도 가린 글이라, AI Hub 정상 오경보 0.7% 같은 수치는 실제 이름과 번호가 든 통화보다 좋게 나왔을 수 있다. 진짜 이름과 번호가 든 실제 정상 통화로는 아직 재지 않았다.

## 도는 곳 정리

- **GPU가 필요한 것:** Whisper large-v3 하나.
- **CPU로 되는 것:** 통화 분류기, 문자 분류기, 유사 사례 검색, 규칙, 로컬 화자 분리.
  - 노트북 CPU에서 통화 분류기는 조각 하나에 0.5–2초가 걸려 동시 통화가 많으면 밀린다.
- **리턴제로로 보내는 것 (음성):** 통화 중 재전사, 통화 뒤 전체 재전사, 녹음 파일 분석.
- **Anthropic API로 보내는 것 (글, 문서 사진):** 상태 추적기, 대응 에이전트, 문자 판별 보조, 문서 판별, 수사 분석, 신종 수법 카드.
