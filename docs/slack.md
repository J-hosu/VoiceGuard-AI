# Slack에서 쓰는 절차 안내

[← README로 돌아가기](../README.md) · [절차 안내](guidance.md) · [수사 지원](investigator.md)

**수사관이 Slack에서 사건의 절차 안내를 보고, 조문을 찾고, 확인한 사실을 넣을 수 있습니다.** 조회는 말과 명령으로 하고, 입력은 양식으로만 받습니다.

> [!IMPORTANT]
> 시연 단계의 기능입니다. 서버 쪽 동작은 Slack이 보내는 것과 같은 모양의 서명된 요청으로 자동 시험했지만, 실제 Slack 워크스페이스에 앱을 설치해 확인하지는 않았습니다. 이 기능을 켜면 사건 정보가 Slack 서버에 저장되므로, 실제 수사 정보에 쓰려면 소속 기관의 보안 기준을 먼저 확인해야 합니다.

## 할 수 있는 일

| 하는 일 | Slack에서 | 처리 방식 |
| --- | --- | --- |
| 말로 묻기 | `@VoiceGuard 51번 사건은 어디에 통보해야 해?` | 수사 지원 도우미가 저장된 조문과 수사 데이터를 찾아 스레드에 답합니다. 도우미는 읽기만 합니다 |
| 사건 안내 보기 | `/vg 사건 51` | 규칙표가 계산한 절차 안내를 카드로 보여 줍니다. AI를 거치지 않습니다 |
| 조문 찾기 | `/vg 법령 범죄인 인도 청구` | 받아 둔 조문을 그대로 보여 주고 국가법령정보센터 링크를 붙입니다 |
| 사건 사실 넣기 | `/vg 입력 51` 또는 카드의 ‘사건 사실 입력’ 버튼 | 입력 양식이 열립니다. 저장하면 규칙표로 다시 계산한 결과를 채널에 올립니다 |
| 기한 보기와 알림 | `/vg 기한`, 자동 알림 | 기한이 내일·오늘이거나 지난 사건을 정해 둔 채널에 알립니다 |

## 조회는 말로, 입력은 양식으로

- **조회**는 틀려도 다시 물으면 되므로 말로 받습니다. 도우미는 조문 찾기와 절차 안내를 도구로 불러와 인용할 뿐, 사건 사실을 고칠 수 없습니다.
- **입력**은 양식으로만 받습니다. 이득액이 5억 원을 넘는지, 인지한 날이 언제인지에 따라 통보 여부와 기한이 달라지므로, AI가 숫자나 날짜를 옮겨 적다가 틀리면 판정이 바뀌기 때문입니다.
- 양식에는 수사관이 확인해 저장한 값만 채워집니다. 통화 기록에서 자동 추정한 값은 칸 아래에 적혀 있고, 맞으면 같은 값을 골라 확정합니다. 그대로 두고 저장해도 추정값이 확인한 사실로 바뀌지 않습니다.
- 저장하면 누가 어떤 항목을 바꿨는지 기록에 남고(`case_fact_log`), 채널에도 바뀐 항목이 함께 올라갑니다.

## 설정

1. **Slack 앱을 만듭니다.** <https://api.slack.com/apps>에서 ‘Create New App → From a manifest’를 고르고 [`slack/app_manifest.yaml`](../slack/app_manifest.yaml)의 내용을 붙여 넣습니다. 세 주소의 `YOUR-SERVER`는 서버의 공개 주소로 바꿉니다.
2. **워크스페이스에 설치합니다.** ‘Install App’에서 설치한 뒤 Bot User OAuth Token(`xoxb-…`)과 ‘Basic Information’의 Signing Secret을 확인합니다.
3. **서버의 `.env`에 값을 넣고 서버를 다시 시작합니다.**

   ```env
   SLACK_BOT_TOKEN=xoxb-...            # 봇 토큰
   SLACK_SIGNING_SECRET=...            # Slack이 보낸 요청인지 확인하는 값
   SLACK_ALLOWED_CHANNELS=C0123456789  # 사건을 볼 수 있는 채널 ID(쉼표로 여러 개)
   SLACK_ALLOWED_USERS=U0123456789     # 사건 사실을 넣을 수 있는 사용자 ID(쉼표로 여러 개)
   SLACK_DEADLINE_CHANNEL=C0123456789  # 기한 알림을 받을 채널(선택)
   ```

4. **Slack 앱 설정의 ‘Event Subscriptions’에서 주소 확인을 다시 누릅니다.** 서버가 서명 비밀값을 알기 전에는 확인에 실패하기 때문입니다.
5. **봇을 채널에 초대합니다.** `/invite @VoiceGuard`

채널 ID와 사용자 ID를 모르면 먼저 명령을 한 번 실행해 보십시오. 허용 목록에 없다는 안내에 그 채널과 사용자의 ID가 함께 나옵니다.

| 환경 변수 | 뜻 |
| --- | --- |
| `SLACK_BOT_TOKEN`, `SLACK_SIGNING_SECRET` | 둘 다 있어야 Slack 요청을 받습니다. 하나라도 없으면 `/slack/*` 주소는 503을 돌려줍니다 |
| `SLACK_ALLOWED_CHANNELS` | 사건 안내와 조문 찾기를 쓸 수 있는 채널. 비워 두면 아무 채널에서도 쓸 수 없습니다. `*`는 모든 채널 |
| `SLACK_ALLOWED_USERS` | 사건 사실을 넣을 수 있는 사람. 비워 두면 아무도 넣을 수 없습니다. `*`는 모든 사람 |
| `SLACK_TEAM_ID` | 적어 두면 그 워크스페이스에서 온 요청만 받습니다(선택) |
| `SLACK_DEADLINE_CHANNEL` | 기한 알림을 올릴 채널. 없으면 알림을 보내지 않습니다 |
| `SLACK_DEADLINE_HOURS` | 알림을 보내는 시간대(한국 시간, 기본 `8-20`) |
| `SLACK_DEADLINE_VIA_N8N` | `1`이면 봇 대신 n8n 웹훅으로 기한 알림을 보냅니다(아래 참고) |

## 기한 알림

- 서버가 15분마다 사건 사실이 저장된 통화의 기한을 확인합니다. 기한 전날, 당일, 지난 뒤에 한 번씩 알립니다.
- 전달이 확인된 알림만 ‘보냄’으로 기록하고, 실패한 알림은 다음 확인 때 다시 보냅니다.
- 봇 토큰이 없는 서버에서는 n8n으로 보낼 수 있습니다. `SLACK_DEADLINE_VIA_N8N=1`로 두면 `guidance.deadline` 이벤트를 `N8N_WEBHOOK_URL`로 보내고, [`n8n/voiceguard_slack_alert.json`](../n8n/voiceguard_slack_alert.json) 워크플로가 Slack에 올립니다. 이미 가져온 워크플로에는 ‘알림 문구 만들기’ 노드에 이 이벤트의 분기를 추가해야 합니다.
- 지금 바로 확인하려면 `POST /guidance/deadlines/notify`를 부릅니다. 기한 목록은 `GET /guidance/deadlines`로 볼 수 있습니다(둘 다 관리 경로).

## 지키는 것

- **서명 확인**: Slack이 보낸 요청인지 요청마다 서명으로 확인하고, 5분이 지난 요청은 받지 않습니다. 접속 코드 게이트는 Slack이 부르는 세 주소(POST)만 지나가게 합니다.
- **허용 목록**: 채널과 사용자를 적어 둔 것만 허용합니다. 비워 두면 거부합니다. 대시보드가 관리 코드로 막는 것과 같은 이유입니다.
- **3초 안에 응답**: 저장과 다시 계산까지만 하고 바로 답한 뒤, 채널에 글을 올리는 일과 도우미의 답은 뒤에서 처리합니다.
- **미리보기 끄기**: 봇이 올리는 글에서는 링크 미리보기를 꺼, Slack이 바깥 주소를 대신 불러오지 않게 합니다.
- **토큰과 서명 비밀값**은 기록이나 오류 문구에 남기지 않습니다.

## 시험과 한계

- 자동 시험 31개가 서명 확인, 명령, 카드, 입력 양식, 저장과 기록, 멘션, 기한 알림, 주소와 게이트를 확인합니다. Slack과 Claude는 가짜로 바꿔 부릅니다.
- 구현하지 않은 검토자가 세 관점에서 검토했고, 재현된 지적 20건을 모두 반영했습니다.
- 실제 Slack 워크스페이스에서는 확인하지 않았습니다. Slack 화면에서 카드와 양식이 보이는 모양은 설치한 뒤에 확인해야 합니다.
- 서버가 켜져 있어야 동작합니다. 도우미의 답에는 Claude API 키가 필요합니다.
- 허용한 채널에 있는 사람은 누구나 사건 안내를 볼 수 있습니다. 비공개 채널을 쓰십시오.
